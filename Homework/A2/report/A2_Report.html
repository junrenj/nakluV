A2: Materials by Jimmy Jian (junrenj)

In this system, a Material is essentially the equivalent of a Material Instance in Unreal Engine 5. I have already pre-configured the data within the Urenderextractor. To prevent null material issues, the library includes fallback materials such as pure white, pure black, default normals, and a specific 'bug warning' material. Material classification is handled by passing an integer value to the shader, which then triggers the corresponding logic branch. This approach avoids the code bloat associated with creating excessive pipelines and streamlines management.

I spent a significant amount of time refactoring Professor Jim's code for Compute Shader image processing. Specifically, I transitioned the system from Image2D to Cubemap support and integrated a workflow to generate and upload mipmaps via Vulkan Blit operations.

Current pending task: The pre-processed roughness maps still exhibit significant noise, particularly when generating low-resolution outputs.

Using the Cube Utility

The system provides three core functionalities for IBL pre-processing:
1. Irradiance Map Generation: Processes an input cubemap to generate a diffuse irradiance map.
2. Pre-filtered Specular Mipmaps: Generates pre-computed specular environment maps (currently hard-coded to 5 mip levels).
3. BRDF LUT Generation: Directly generates a 2D Lookup Table (LUT) for specular integration.
